# Airport troubles [80 marks]

The Intergalactic Institute of Misinformation Technology is ready for the 3067 batch of UG-1s. Double sharing rooms have been converted to triple sharing, and mess food has been upgraded (for a few days). Students from all the nearby galaxies are flying in. Advancements in technology have caused the institute to have its very own airport, Gotham Intergalactic Airport. Spaceship GB-420 has just landed there. Before the students can start their new lives, they have to get through immigration and collect their bags from the baggage belt. Can you help the students of Spaceship GB-420 get through the arrivals section?

For this section, you will be simulating this arrivals area. Every person in the airport **must be modelled as a thread**. Their jobs are:

- **Students** enter the immigration hall, scan their passport at one of the scanners, receive a stamp, leave the hall, collect their bag from the belt and exit.
- **The immigration officer** enters the hall, approves all the students in it at once and leaves.
- **Baggage handlers** load bags from the spaceship onto the belt. The handler queues loading Student `i`'s bag onto the belt. If the queue has space, it's loaded immediately. Else, it's blocked until a spot on the belt is freed up.

**There are 2 baggage handlers, the belt holds at most 2 bags, and every student has exactly one bag. Any number of students can be in the hall at once. The hall has 3 passport scanners, and each serves one student at a time.**

If every scanner is in use, a student waits in the hall until one is free. If several students are waiting, any one of them may take the free scanner.

### Constraints [10 marks for satisfying each]

1. While the officer is in the hall, no one may enter and students may not leave.
2. The officer must wait until every student in the hall has scanned their passport, including those waiting for a scanner. She then approves everyone in the hall as one batch (this counts as one action for the purpose of the assignment).
3. A student can receive a stamp only after being approved. The officer leaves right after approving, without waiting for the stamps to be issued. If there is no one to approve, she still approves an empty batch and leaves.
4. Students cannot leave the hall until they have received a stamp.

> Note: You can assume every student eventually receives a stamp, so no student is left waiting in the hall after the officer's last visit.

5. A handler cannot load a bag until its owner has received a stamp. Any handler may load any ready bag, in any order. If the belt is full, a handler waits with her bag until a student collects one.
6. A student can collect only their own bag, and only after leaving the hall. If their bag is not on the belt yet, they wait until a handler loads it. After collecting it, they leave the airport.
7. Every bag whose owner receives a stamp is loaded and collected exactly once. No other bag is loaded.
8. Every action takes 1 time unit, except `scans passport`, which takes 2 time units.

The action times are just symbolic. Your aim is to run a simulation of the actions, which means you need not actually wait for 2 seconds for scanning a passport. Any calls to `usleep` or similar that we find in your code will be considered **suboptimal solutions** and **may be penalized**.

### Input format

First line: a single integer `N` containing the number of lines that will be entered next.

Next `N` lines: three space-separated values each, `<time> <actor> <id>`.

`<actor>` can be one of `Student` or `Immigration officer`. `Baggage handler` isn't part of the input since their action times are dependent on the stamp receipt times.

### Output format

Output each action in the format `<time> <actor> <id> <action>`.

Lines with the same timestamp must be processed in the order in which they are given. There is only one immigration officer, with the ID 1. The baggage handlers have IDs 1 and 2. 

The actors will have the following actions:

- Students: `enters`, `scans passport`, `receives stamp`, `leaves hall`, `collects bag`
- Officer: `enters`, `approves`, `leaves`
- Handlers: `loads bag for Student <i>`

# Symbolic links in xv6 [60 marks]

In this exercise, you will be implementing symbolic links (a.k.a soft links/symlinks/shortcuts) in xv6.
This is a mechanism that lets a file "point" to another file, meaning that opening, reading from and writing to this symlink will have the same effect as dealing with the original.

For this exercise, you won't need to implement symlinks to directories or devices. Symlinks to files is sufficient.

Here's an example of what your implementation would look like when finished:
```shell
$ echo "a" > file1
$ ln -s file1 file2
$ cat file2
"a"
$ echo "b" >> file2
$ cat file1
"a"
"b"
$ rm file1
$ cat file2
// error
```

Your solution (for the kernel part) is correct if it passes `usertests -q` and `symlinktest`. Userspace programs will be manually tested.

## The `symlink` system call [20 marks]

Implement an `int symlink(char* target, char* path)` which creates a symlink at `path` pointing to `target`. Dangling symlinks are allowed, so the target path need not exist for a successful call.

The call must return `0` if successful, and `-1` if a failure occurred.

## The `open` system call [20 marks]

You will need to modify the `open` system call to follow symlinks. Also, add an `O_NOFOLLOW` flag to avoid following symlinks. This will come in handy when building the `readlink` program later. If the symlink destination is also a symlink, you must keep following until you reach a file which is not a symlink. To avoid infinite loops, **traverse up to a maximum depth of 10**.

As far as this exercise is concerned, `open` will be the only system call that needs to follow symlinks.

## The `ln` user program [10 marks]

Modify the `ln` user program to handle soft linking. If called with the `-s` flag, create a soft link. Otherwise, stick to the usual hard linking behaviour.

### Example usage

```bash
ln -s README.md README # Creates a soft link called README pointing to README.md
```

```bash
ln README.md README # Creates a hard link called README pointing to README.md
```

You may assume that the `-s` flag, if present, will only be passed as the second argument.

## The `readlink` user program [10 marks]

This program must take in the path of a symlink and print the path of the file it points to. The xv6 kernel won't compile without this.
If the given path is not of a symlink, print out a corresponding error message and exit with a non-zero status.

### Example usage

```bash
$ readlink README
README.md
```

```bash
$ readlink README.md
# Prints an error message
```

## Hints

- Add a new inode type (`T_SYMLINK`) to `kernel/stat.h` to represent a symbolic link. `symlinktest` won't compile before that.
- Think about where you'll store the destination path for a symlink (the inode's data blocks are a convenient choice).


# Birthday boy [30 marks]

It's your roommate's birthday and you are tasked with bringing him to JC at 11:55PM while your friends set up the cake. You remain with him in his lab till 11:40, but to your dismay, he leaves the lab at 11:45 and goes missing. This is the second year in a row that this has happened.

You and your friends come to the conclusion that he would have gone to the location closest to his lab. You decide to trace all possible places where he could have gone to and find the shortest path there. To speed up the process, you need to parallelize the shortest-path finding algorithm using your knowledge of threads.

## The Bellman-Ford algorithm [10 marks]

Modelling the campus as a graph with `V` vertices and `E` edges, your task is to find the shortest path from a given node `N` to any other node using the **Bellman-Ford algorithm**. You are required to use threads to speed up the algorithm.

You may assume that the graph has no negative cycles.

### Input format
First line: space-separated integers `V E N T` which are the number of vertices, number of edges, the source node and the number of threads which will be spawned, respectively.

Then follow `E` lines with two space-separated integers each: `S D` which are the endpoints of the edge. `S` and `D` are zero-indexed identifiers for the vertices. Edges are bidirectional.

### Output format
`V` space-separated integers, where integer `i` is the length of the shortest path from `N` to `i`.

### Example

Input:
```
6 7 0 4
0 1
0 2
1 3
2 3
3 4
1 2
4 5
```

Output:
```
0 1 1 2 3 4
```
